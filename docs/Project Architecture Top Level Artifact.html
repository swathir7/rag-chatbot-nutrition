Terms in plain English

  • RAG Find relevant text first, then let the LLM answer from it.
  • Chunk A small piece of a document (one section, up to 800 tokens).
  • Embedding A list of 512 numbers that captures what a text means.
  • Cosine similarity How close two embeddings are, from 0 to 1.
  • Top-k How many best-matching chunks to keep (3).
  • Threshold Minimum score a chunk needs to be used (0.75).
  • Zod Checks the LLM's JSON has the right shape.

Why these choices

  • RAG: Milestone 1 made up sources and numbers.
  • Split by heading: every chunk keeps its section name for citations.
  • Local embeddings: free, no API key, fits in 512 MB.
  • SQLite, not Chroma: Chroma crashed on Render's CPUs; 563 vectors is small enough to scan.
  • Regex guard: medical refusals are enforced in code, not by the prompt.
  • Server fixes sources: the LLM can't invent a publisher, year or link.
  • Groq: fast, free tier, same stack as Milestone 1.

Weak spots to admit

  • Gate is loose: off-topic questions score 0.77add a reranker
  • Refusals are detected by matching wordsadd a status field to the JSON
  • Eatwell parsed to 168 characters; Australian chunks lost their headingsOCR and better heading detection

Quick interview answers

  • Why RAG?So answers come from real documents I can cite, not the model's memory.
  • How did you chunk?By heading, max 800 tokens, 100 overlap. Long sections get force-split.
  • Two kinds of refusal?Out of scope: blocked by regex. Not in documents: blocked by the gate or the prompt.
  • How do you stop fake citations?The server overwrites each source with the retrieved chunk's real metadata.
  • Bad JSON from the LLM?Zod check, one retry at lower temperature, then a safe fallback answer.
  • Results?71.4% retrieval hit rate (10/14). Medical questions blocked before any search.
  • How to scale?Vector index (pgvector), keyword + vector search, a reranker, streaming.
  • Chat memory?Session id in the browser; the last 4 messages are sent with each question.
